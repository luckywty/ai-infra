# 第一优先级：必须认真学习

## Lec 2：PyTorch, Resource Accounting

这是你第一阶段最重要的一讲之一。

需要掌握：

- Tensor 的 shape、dtype 和 device；
- FP32、FP16、BF16 显存差异；
- 模型参数量和权重显存估算；
- 激活显存；
- FLOPs 估算；
- Arithmetic Intensity；
- Memory Bound 和 Compute Bound；
- GPU 理论算力和显存带宽；
- 推理性能测量方法。

这一讲直接决定你后面能不能分析：

- 为什么 Decode 偏显存带宽受限；
- 为什么 Prefill 更容易利用 Tensor Core；
- 为什么量化可能提高 Decode 速度；
- 为什么模型明明放得进显存，却无法支持高并发。

### 学完后必须做的实验

选一个 0.5B—3B 模型，计算并验证：

1. FP32、FP16、BF16 权重显存；
2. 不同 batch 和序列长度的显存变化；
3. 不同 Prompt 长度的推理时间；
4. 不同输出长度的推理时间；
5. `torch.no_grad()` 与 `torch.inference_mode()`；
6. 模型加载时间和稳态推理延迟分开统计。

产出：

```text
benchmark_hf.py
resource_accounting.md
```

不要只看课程。

## Lec 3：Architectures, Hyperparameters

这一讲是理解 LLM 推理数据流的核心。

重点学习：

- Transformer Decoder；
- RMSNorm；
- Attention；
- RoPE；
- MHA、MQA、GQA；
- FFN 和 SwiGLU；
- Residual；
- Vocabulary 和 LM Head；
- Hidden Size；
- Head Dimension；
- Layer 数量；
- KV Head 数量。

你不需要深入研究如何选择预训练超参数，但必须清楚模型配置如何影响推理。

例如：

- 层数增加会怎样影响 KV Cache；
- Hidden Size 增加会怎样影响 GEMM；
- KV Head 减少为什么会降低显存；
- Vocabulary 变大会怎样影响 LM Head；
- Context Length 增加为什么会明显增加 KV Cache。

### 学完后必须实现

使用 PyTorch 实现：

```text
mini_llm/
├── rmsnorm.py
├── rope.py
├── attention.py
├── kv_cache.py
├── decoder_layer.py
└── test_shapes.py
```

不要求训练，只要求前向计算正确。

## Lec 5：GPUs

这讲是进入 CUDA 和 Triton 之前的基础。

重点学习：

- GPU 和 CPU 的区别；
- SM；
- Warp；
- Thread Block；
- SIMT；
- Global Memory；
- Shared Memory；
- Register；
- Cache；
- Tensor Core；
- 显存带宽；
- 延迟隐藏；
- Occupancy；
- Roofline 模型。

你需要能够将这些概念与 LLM 算子对应：

|GPU 概念|LLM 推理中的对应问题|
|---|---|
|显存带宽|Decode 反复读取权重和 KV Cache|
|Tensor Core|Prefill 中的大矩阵乘法|
|Shared Memory|Reduction、Softmax、Attention Tiling|
|Kernel Launch|Decode 中大量小 Kernel 开销|
|Occupancy|Kernel 并行度和资源使用|
|Arithmetic Intensity|判断计算受限或带宽受限|

### 课程搭配

这一讲需要同步搭配 GPU MODE：

- CUDA 入门；
- GPU Compute and Memory Architecture；
- CUDA for Python Programmers。

不能只靠 CS336 的一讲掌握 CUDA。

## Lec 7：Parallelism 1

只学习与推理有关的部分。

重点：

- Data Parallel 基本概念；
- Tensor Parallel；
- Column Parallel Linear；
- Row Parallel Linear；
- AllReduce；
- AllGather；
- ReduceScatter；
- 通信与计算的关系；
- 模型为什么需要多卡；
- 多卡后为什么不一定线性加速。

其中最重要的是 Tensor Parallel。

你要能解释：

- 一个 Linear 层如何切到多张 GPU；
- 为什么 Row Parallel 通常需要 AllReduce；
- 为什么通信会影响 Decode；
- Tensor Parallel 度数过高为什么可能反而变慢。

### 短期不要求

- 自己实现完整 Tensor Parallel；
- 多节点训练；
- DeepSpeed 训练；
- Megatron 完整源码。

10 周内理解原理并在 vLLM 中尝试配置双卡 TP 即可。

# 第二优先级：选择性学习

## Lec 1：Overview and Tokenization

建议花半天到一天学习，不需要投入一整周。

你需要知道：

- BPE 是什么；
- Tokenizer 为什么影响序列长度；
- Token 数量如何影响 Prefill、Decode 和 KV Cache；
- 中文、英文和代码的 Token 密度不同；
- Tokenization 不是字符级处理。

不需要短期完成：

- 高性能 BPE 训练器；
- 完整 Tokenizer 优化；
- 大规模语料 Tokenizer 训练。

对推理优化而言，Tokenizer 通常不是主要 GPU 瓶颈，但它会影响请求输入长度、TTFT 和成本，因此需要理解。

短期只学习概念，不要深挖实现。

重点理解：

- Dense 模型与 MoE 模型区别；
- Router；
- Top-k Expert；

- Expert Parallel；

- 热点专家；

MoE 是当前推理 Infra 的重要方向，但不应放在你前四周。

建议在第 9—10 周或者三个月扩展阶段学习。

## Lec 12：Evaluation

只学习和推理优化有关的部分：

- Perplexity；
- Accuracy；
- Benchmark；
- 量化前后质量对比；
- 性能和精度权衡；
